# Подробный гайд по модулю `survival`

## Для чего нужен этот модуль

Модуль `survival` решает две связанные, но разные задачи:

1. `Survival LQ fitter`
   - оценивает эффективные радиобиологические параметры по данным динамики объёма опухоли;
   - сравнивает модели;
   - строит производные радиобиологические метрики;
   - помогает понять, какие серии годятся для какого анализа.

2. `Tumor growth predictor`
   - использует уже имеющиеся `alpha` и `beta` для прямого прогноза;
   - моделирует рост опухоли во времени;
   - показывает кривые объёма;
   - строит 3D-эллипсоид по измерениям `a-b-c`;
   - поддерживает mixed-family расписания, sensitivity analysis и scenario comparison.

Это руководство описывает работу с обоими окнами и типовые пользовательские сценарии.

## Что считается входными данными

### 1. Excel-файлы опухолевых серий

Основной формат входа для fitter и predictor:

- `.xlsx` файл;
- в первой строке находятся параметры эксперимента;
- во второй строке обычно находятся временные точки;
- далее идут данные по животным.

В ячейках опухолевых измерений могут быть:

- тройки размеров в формате `a-b-c`;
- либо уже рассчитанный объём.

### 2. Control-файлы

Control-файлы распознаются по слову `control` в имени файла.

Примеры:

- `control_2016.xlsx`
- `control.xlsx`

Если control-файлов несколько, в `Survival LQ fitter` их нужно сопоставлять вручную через `Experiment to control mapping`.

### 3. Метаданные облучения

Для timing-aware моделей важны метаданные в первой строке Excel.

Поддерживаются, в частности:

- фракции по имени файла или заголовку, например `y_40`, `y4_y4_y32`, `p23_p23_in_peak`;
- интервалы между фракциями через `t=...`, например:
  - `t = 30 min`
  - `t = 1 hr`
  - `t = 2.5 hr`
  - `t = 1 day`
  - `t = 1 ч./1 сут./1 ч.`
- длительность самой фракции через маркеры вроде:
  - `tau`
  - `t_irr`
  - `duration`

Если в одной ячейке указано несколько интервалов через `/`, программа теперь умеет читать и смешанные единицы времени. Например:

- `t=1 ч./1 сут./1 ч.`
- `t=30 мин/2.5 ч/1 сут`
- `t=1ч/24ч/1ч`

### 4. Файлы skin/RTOG

Для `NTCP` можно загружать отдельные Excel-файлы с кожными реакциями.

Поддерживаются два режима:

- `Legacy skin scale`
- `RTOG grades`

Если используется `Legacy skin scale`, приложение само переводит её в `RTOG`.

## Как модуль определяет тип излучения

Приложение автоматически выводит `family` из имени файла.

Поддерживаются:

- `y`
- `p`
- `p_peak`
- `p_through`
- `n`
- `e`
- `c`

Практически это означает:

- `y` — гамма/фотоны;
- `p_peak` — протоны в пике;
- `p_through` — протоны в простреле;
- `n` — нейтроны;
- `e` — электроны;
- `c` — ионы углерода.

Примеры:

- `22.10.2025_p40_in_peak.xlsx` -> `p_peak`
- `08.10.2021_p_32_прострел.xlsx` -> `p_through`
- `05.12.2018_c_12.xlsx` -> `c`

Если family определена неверно, это почти всегда проблема имени файла.

## Когда использовать какое окно

### Используйте `Survival LQ fitter`, если нужно

- оценить `alpha` и `beta`;
- сравнить `classic_lq`, `repair_lq`, `repair_biexp`, `glq`, `lq_l`, `lq_repop`, `repair_repop`, `linear`, `let_dependent`;
- понять, насколько данные вообще пригодны для фита;
- посчитать `RBE`, `TCP`, `NTCP`;
- сравнить `SF`-метрики;
- выгрузить summary в CSV.

### Используйте `Growth predictor`, если нужно

- смоделировать динамику конкретной опухоли во времени;
- спрогнозировать объём и `a-b-c`;
- посмотреть влияние интервалов между фракциями;
- сравнить два сценария облучения;
- смоделировать mixed-family расписание;
- анимировать 3D-эллипсоид.

## Окно `Survival LQ fitter`

### Общая логика окна

Окно состоит из двух частей.

Слева:

- кнопки `Run fit`, `Inventory`, `Growth predictor`;
- вкладки `Files` и `Fit setup`.

Справа:

- верхняя таблица `Run summary`;
- поле `Selected run`;
- нижние вкладки:
  - `Training`
  - `Validation`
  - `Bootstrap`
  - `Cross-validation`
  - `Inventory`
  - `Summary text`
  - `Analysis`
  - `TCP`
  - `NTCP`

### Вкладка `Files`

Раздел называется `Files and controls`.

Здесь есть:

- `Add files`
- `Folder`
- `Remove`
- `Clear`
- список файлов;
- таблица `Experiment to control mapping`

Как это работает:

- `Add files` добавляет отдельные `.xlsx`;
- `Folder` добавляет все `.xlsx` из папки;
- `Remove` убирает выбранные строки;
- `Clear` очищает текущий список.

Если в списке есть несколько control-файлов, каждому treated-файлу нужно выбрать свой control в `Experiment to control mapping`.

- `Bootstrap`

- `Repair T1/2 (h)`
- `Fast repair T1/2 (h)`
- `Slow repair T1/2 (h)`
- `Aggregate repeats`
- `Deduplicate`
- `Fast fraction`

- `Summary CSV`
- `Browse`

Ниже — как использовать эти поля.

## Что означает каждая основная настройка fitter-а

### `SF modes`

Поддерживаются:

- `absolute`
- `absindex:1`
- `absindex:2`
- и другие `absindex:N`

Практический смысл:

- `absolute` — самый типичный вариант для scalar-анализа;
- `absindex:N` — полезно, если нужен ответ на фиксированной временной точке, а не минимум кривой.

Если вы не уверены, начните с:

- `absolute`

Если хотите проверить устойчивость вывода:

- `absolute, absindex:1, absindex:2`

### `Family`

Позволяет ограничить fit одной family.

Варианты:

- `all`
- `y`
- `p`
- `p_peak`
- `p_through`
- `n`
- `e`
- `c`

Если вы работаете с одной серией, почти всегда лучше выбрать конкретную family, а не `all`.

### `By family`

Если включено, fitter разбирает все найденные family по отдельности.

Это особенно полезно, когда в папке лежат:

- гамма;
- протоны;
- нейтроны;
- электроны;
- углерод.

### `Default control` и `Apply to all`

Используются только для удобства заполнения `Experiment to control mapping`.

Рекомендуемый сценарий:

1. Сначала загрузите все treated и control файлы.
2. Выберите самый частый control в `Default control`.
3. Нажмите `Apply to all`.
4. После этого вручную поправьте те серии, для которых нужен другой control.
5. Затем нажмите `Inventory`, чтобы пересчитать `fit ready`, `notes` и сводку по данным.

Важно:

- `Apply to all` теперь меняет mapping быстро и без автоматического пересчёта `Inventory`;
- это сделано специально, чтобы окно не подвисало на больших папках;
- сам fit использует актуальный mapping сразу, но для обновления диагностической сводки нужен явный `Inventory`.

### `Fit kind`

Определяет, на каких режимах обучается модель.

Варианты:

- `all`
- `single`
- `fractionated`

Практика:

- если хотите сначала оценить базовую dose-response, используйте `single`;
- если хотите подогнать всё вместе, используйте `all`;
- `fractionated` имеет смысл только для специальных задач.

### `Validate kind`

Определяет holdout-набор.

Варианты:

- `none`
- `all`
- `single`
- `fractionated`

Наиболее полезный научный сценарий:

- `Fit kind = single`
- `Validate kind = fractionated`

Это позволяет проверить, предсказывает ли модель фракционированные режимы, обучившись только на однократных дозах.

### `Response mode`

Варианты:

- `scalar`
- `curve`

Когда использовать:

- `scalar`
  - если вы хотите классический fit по одному `SF` на режим;
  - если данных мало;
  - если хотите быстрее сравнить модели.
- `curve`
  - если хотите использовать всю нормированную кривую объёма;
  - если хотите более устойчивый fit на длинных сериях;
  - если вас интересует не только итоговый `SF`, но и форма отклика.

### `Model`

Поддерживаются:

- `auto`
- `classic_lq`
- `repair_lq`
- `repair_biexp`
- `glq`
- `let_dependent`
- `repair_repop`
- `lq_l`
- `lq_repop`
- `linear`

Краткие рекомендации:

- `classic_lq`
  - стартовая базовая модель;
  - используйте, если timing не критичен.
- `repair_lq`
  - если интервалы между фракциями важны и есть `t=...`.
- `repair_biexp`
  - если хотите более сложную repair-модель с fast/slow компонентами.
- `glq`
  - для больших доз, когда обычный LQ может вести себя слишком жёстко.
- `lq_l`
  - ещё один high-dose вариант.
- `lq_repop`
  - если хотите учесть поздний regrowth/repopulation.
- `repair_repop`
  - когда нужны и timing, и repopulation.
- `linear`
  - простой baseline.
- `let_dependent`
  - когда хотите одну непрерывную модель `LET -> alpha`, а не отдельные независимые family-fit'ы.

### `Compare models`

Если включено, fitter сравнит несколько моделей на одном и том же train-наборе.

Используйте это, если:

- вы не уверены, какая модель уместнее;
- хотите сравнить `classic_lq` против `glq`, `lq_l`, `repair_lq` и других;
- готовите результаты для диссертации или статьи.

### `Fix alpha`

Включает режим, когда `alpha` фиксируется вручную, а fitter оценивает остальное.

Используйте это, если:

- данных мало;
- `alpha` хотите взять из внешнего источника;
- хотите проверить устойчивость `beta`.

### `Repair T1/2 (h)`

Главная настройка для timing-aware анализа.

Если значение:

- `0`
  - используется классическая schedule-free логика;
- больше `0`
  - модель начинает различать интервалы между фракциями.

Это важно для схем с:

- `30 min`
- `1 h`
- `2.5 h`
- `24 h`

### `Fast repair T1/2 (h)`, `Slow repair T1/2 (h)`, `Fast fraction`

Используются для `repair_biexp`.

Имеют смысл только если:

- вы реально хотите би-экспоненциальную repair-модель;
- в данных есть достаточно timing-контраста.

### `Aggregate repeats`

Рекомендуется, если в папке есть несколько повторов одного и того же режима.

Например, несколько `y_36` или несколько повторных серий одного фракционирования.

Эта опция:

- усредняет повторные режимы;
- хранит `Repeats` и `SF std`;
- уменьшает шум.

### `Deduplicate`

Оставляет только один файл на одинаковый regimen.

Используйте осторожно. Обычно для научной работы полезнее `Aggregate repeats`, а не `Deduplicate`.

### `Summary CSV`

Если указать путь, fitter сохранит summary результатов в CSV.

Это удобно для:

- работы с большим числом family;
- последующего анализа в Excel, Python или R;
- подготовки таблиц в диссертацию.

## Рекомендуемые сценарии работы в `Survival LQ fitter`

### Сценарий 1. Быстрый fit одной family

Подходит, если у вас:

- один control;
- несколько treated-файлов;
- одна family, например `y`.

Шаги:

1. Откройте `Files`.
2. Нажмите `Add files` или `Folder`.
3. Убедитесь, что control-файл тоже загружен.
4. В `Fit setup` установите:
   - `SF modes = absolute`
   - `Family = y`
   - `Fit kind = all`
   - `Validate kind = none`
   - `Response mode = scalar`
   - `Model = auto`
5. Нажмите `Run fit`.
6. Смотрите `Run summary`, затем `Training`, `Summary text`, `Analysis`.

### Сценарий 2. В папке много файлов разных типов излучения

Это один из самых важных практических кейсов.

Рекомендуемый порядок:

1. Нажмите `Folder`.
2. Нажмите `Inventory`.
3. Перейдите в вкладку `Inventory`.
4. Посмотрите:
   - какие family обнаружены;
   - какие файлы распарсились;
   - какие серии `fit ready`;
   - какие причины пропуска.
5. Затем выберите один из путей:
   - либо `Family = y` и анализируйте по одной family;
   - либо включите `By family`, если хотите batch-разбор.

Если файлов очень много, не стоит сразу пытаться сделать один общий fit на всём.

Правильнее:

1. Сначала `Inventory`.
2. Потом отдельно `y`.
3. Потом отдельно `p_peak`.
4. Потом отдельно `p_through`.
5. Потом отдельно `n`, `e`, `c`.

### Сценарий 3. Мало control-файлов, а treated-серий много

Ваш типичный кейс.

Как работать:

1. Загрузите все treated-файлы и все доступные control-файлы.
2. В `Default control` выберите самый частый control.
3. Нажмите `Apply to all`.
4. В таблице `Experiment to control mapping` вручную поменяйте control там, где это нужно.
5. Нажмите `Inventory`, чтобы увидеть, не осталось ли неоднозначностей.
6. Только после этого запускайте `Run fit`.

### Сценарий 4. Обучение на однократных дозах, проверка на фракционированных

Это один из самых сильных научных режимов.

В `Fit setup` поставьте:

- `Fit kind = single`
- `Validate kind = fractionated`

Остальное обычно:

- `Response mode = scalar`
- `SF modes = absolute`
- `Model = classic_lq` или `auto`

После `Run fit` смотрите:

- `Validation`
- `Cross-validation`
- `Summary text`

### Сценарий 5. Важны интервалы между фракциями

Если у вас есть:

- `30 min`
- `1 h`
- `2.5 h`
- разные интервалы между одинаковыми дозами

ставьте:

- `Repair T1/2 (h) > 0`

Если хотите более сложную repair-модель:

- `Model = repair_biexp`
- задайте `Fast repair T1/2 (h)`, `Slow repair T1/2 (h)`, `Fast fraction`

После этого смотрите:

- `Training`
- `Validation`
- `Summary text`
- `G`
- `Cross-validation`

### Сценарий 6. Сравнение high-dose моделей

Если у вас крупные дозы и хочется понять, что лучше:

- `classic_lq`
- `glq`
- `lq_l`

поставьте:

- `Compare models`

Обычно лучше выбирать:

- `Response mode = curve`, если есть хорошие длинные кривые;
- `Response mode = scalar`, если хотите более простой и быстрый прогон.

### Сценарий 7. LET-зависимый fit

Если у вас есть несколько family разного качества излучения и вы хотите не просто отдельные fit'ы, а общий `LET`-тренд:

1. Установите `Model = let_dependent`.
2. Обычно `Family` оставляйте `all`.
3. Используйте совместимый набор серий из разных family.
4. Запустите `Run fit`.
5. Перейдите во вкладку `Analysis`.
6. Выберите:
   - `RBE mode = LET model`

Такой режим полезен именно для меж-family анализа.

### Сценарий 8. Повторы одного режима

Если у вас в папке несколько серий с одинаковым regimen:

- сначала попробуйте `Aggregate repeats`;
- `Deduplicate` используйте только если точно хотите убрать повторы совсем.

### Сценарий 9. Большой batch-анализ по всем family

В `Fit setup`:

- включите `By family`
- при необходимости:
  - `Aggregate repeats`
  - `Compare models`
  - `Bootstrap`
  - `Summary CSV`

Затем:

1. Нажмите `Run fit`.
2. Смотрите `Run summary`.
3. Переключайтесь через `Selected run`.

## Как читать результаты fitter-а

### `Run summary`

Это верхняя таблица со сводкой по каждому run.

Там есть:

- `SF mode`
- `Response`
- `Model`
- `Family`
- `Status`
- объём train/validation набора
- `Alpha`
- `Beta`
- `Alpha/Beta`
- `BED`
- `EQD2`
- `G`
- `R^2`
- `Adj R^2`
- `BIC`
- `CV RMSE`
- `Reason`

### `Training`

Показывает обучающие режимы с колонками:

- `Fractions`
- `Schedule`
- `D`
- `D2`
- `SF`
- `BED`
- `EQD2`
- `G`
- `Pred TCP`
- `Repeats`
- `SF std`

### `Validation`

Показывает holdout-режимы и ошибки предсказания.

Смотрите сюда, если хотите понять, насколько модель реально предсказывает, а не только подгоняет.

### `Bootstrap`

Используйте для оценки устойчивости параметров.

### `Cross-validation`

Это LOO cross-validation.

Если хотите отключить его в CLI, теперь есть:

- `--no-cross-validate-loo`

### `Inventory`

Это не fit.

Это предварительная инвентаризация набора:

- какие файлы есть;
- какие семьи обнаружены;
- какие режимы распарсились;
- какие модели выглядят `recommended`, `possible` или `not_ready`.

### `Summary text`

Здесь обычно удобнее всего читать итоговую интерпретацию run-а:

- параметры модели;
- timing diagnostics;
- LOO;
- средние train-метрики;
- holdout;
- model comparison.

## Вкладка `Analysis`

Раздел `Radiobiology analysis` даёт дополнительные производные анализы.

Ключевые элементы:

- `Reference family`
- `RBE mode`
- `RBE doses (Gy)`
- `Build RBE`
- `Compare SF modes`
- `Export CSV`

### Когда использовать `RBE mode = Per-family fits`

Если у вас уже есть независимые fit-ы по нескольким family и вы хотите сравнить их напрямую с референсом, обычно `y`.

### Когда использовать `RBE mode = LET model`

Если вы сделали один общий `let_dependent` fit и хотите строить `RBE` уже напрямую из LET-модели.

### Что делает `Compare SF modes`

Сравнивает, как меняются параметры между:

- `absolute`
- `absindex:1`
- `absindex:2`

Это полезно для проверки устойчивости вывода к определению `SF`.

### Что экспортируется

Кнопка `Export CSV` может сохранить несколько файлов:

- `..._rbe.csv`
- `..._sf_metrics.csv`
- `..._alpha_let.csv`

## Вкладка `TCP`

Позволяет построить synthetic `TCP`-кривую по fitted-модели.

Поля:

- `Initial volume (cm^3)`
- `Cell density`
- `Dose grid (Gy)`
- `Fractions`
- `Interval (days)`
- `Build TCP`
- `Export CSV`

Когда это полезно:

- если хотите оценить, как меняется вероятность контроля опухоли при разных суммарных дозах;
- если хотите получить клинически более интерпретируемую производную от `SF`.

## Вкладка `NTCP`

Теперь она работает в двух режимах.

### 1. Ручной LKB-режим

Вы задаёте:

- `TD50`
- `m`
- `Dose grid (Gy)`

Затем нажимаете:

- `Build NTCP`

### 2. Автоматический fit из skin/RTOG данных

Поля и кнопки:

- `Threshold grade`
- `Input scale`
- `Load skin files`
- `Fit TD50/m`
- `Clear skin files`

Порядок работы:

1. Нажмите `Load skin files`.
2. Загрузите skin/RTOG Excel-файлы.
3. Проверьте таблицу `Skin/RTOG groups`.
4. При необходимости вручную поправьте `Dose (Gy)`.
5. Нажмите `Fit TD50/m`.
6. После этого `TD50` и `m` обновятся автоматически.
7. Нажмите `Build NTCP`, если хотите перестроить кривую отдельно.
8. При необходимости используйте `Export CSV`.

Что важно:

- бинарный endpoint строится как `peak RTOG >= Threshold grade`;
- `Input scale = Legacy skin scale` включает внутренний перевод вашей старой шкалы в `RTOG`;
- `Input scale = RTOG grades` используется, если в файлах уже лежат grades.

## Когда нажимать `Inventory`

Кнопка `Inventory` нужна не после fit, а до fit.

Её полезно нажимать:

- после загрузки большой папки;
- после изменения control mapping;
- после добавления новых файлов;
- если вы сомневаетесь, что family и regimen распарсились правильно.

Важно:

- после ручной смены control в `Experiment to control mapping` сводка `Inventory` не пересчитывается автоматически;
- после `Apply to all` тоже нужен явный `Inventory`;
- это нормальное текущее поведение интерфейса, а не ошибка.

## Вкладка `Files`

Раздел называется `Files and series`.

Элементы:

- `Treated tumor`
- `Open treated file`
- `Control`
- `Open control file`
- `Tumor`
- `Alpha/Beta source`
- `Fit growth from control`

### Что загружать в `Treated tumor`

Именно treated Excel-файл той серии, которую хотите моделировать.

Он нужен для:

- реальных дней наблюдения;
- объёма;
- `a-b-c`;
- базовой геометрии;
- автоматического заполнения fractions и timing, если они есть в файле.

### Что загружать в `Control`

Control-серию для оценки роста без лечения.

### Что выбрать в `Tumor`

Можно выбрать:

- конкретное животное;
- `Mean across rats`

Рекомендуемый старт:

- `Mean across rats`

### Что делает `Alpha/Beta source`

Позволяет:

- либо использовать `Manual`;
- либо взять `alpha/beta` из одного из результатов fitter-а.

Если у вас mixed-family расписание, predictor дополнительно пытается автоматически подтянуть family-specific параметры для каждой фракции из имеющихся fitter run-ов.

### Что делает `Fit growth from control`

Подгоняет growth-параметры по control-файлу.

Это хороший старт, если вы не хотите вводить `Growth rate r` и `Carrying capacity K` вручную.

## Вкладка `Model`

Раздел называется `Model parameters`.

Здесь есть:

- `alpha`
- `beta`
- `Growth rate r`
- `Carrying capacity K`
- `Clearance rate`
- `Horizon (days)`
- `Step (days)`
- `Repair T1/2 (h)`
- `Geometry mode`
- `TCP cell density`

### Как это использовать

- если источник параметров неясен, сначала подгрузите их из `Alpha/Beta source`;
- затем при необходимости скорректируйте вручную;
- `Repair T1/2 (h)` включайте, если расписание содержит короткие интервалы;
- `Geometry mode`:
  - `Fixed ratios`
  - `Fit from observed shape`

### Когда выбирать `Fixed ratios`

Если хотите более стабильную и консервативную геометрию.

### Когда выбирать `Fit from observed shape`

Если доверяете измерениям `a-b-c` и хотите, чтобы модель подстраивалась под наблюдаемую анизотропию формы.

## Вкладка `Schedule`

Раздел называется `Dose schedule`.

Кнопки:

- `Use treated fractions`
- `Add event`
- `Remove rows`
- `Clear schedule`

Таблица содержит:

- `Time (days)`
- `Dose (Gy)`
- `Family`

Под таблицей есть живая строка:

- `Intervals: ...`

Она показывает то же расписание в операторском виде, например:

- `Intervals: t=1 ч./1 сут./1 ч.`

### Что делает `Use treated fractions`

Автозаполняет расписание по treated-файлу.

Если в файле есть `t=...`, интервалы между фракциями будут восстановлены в днях.

Если интервалы были заданы в смешанном виде, например:

- `t=1 ч./1 сут./1 ч.`
- `t=30 мин/2.5 ч/1 сут`

то после автозаполнения:

- в колонке `Time (days)` вы увидите абсолютные времена в днях;
- а в строке `Intervals: ...` — человекочитаемую интервалную запись.

### Что делать, если интервалы заданы в часах

Ничего дополнительно переводить вручную не нужно.

Программа сама переводит:

- `1 h` -> `1/24 day`
- `30 min` -> `0.5/24 day`
- `2.5 h` -> `2.5/24 day`

Но в таблице `Time (days)` это всё равно будет показано в днях.

Для оператора это не проблема, потому что:

- сама таблица нужна для точного редактирования абсолютных времён;
- строка `Intervals: ...` показывает интервалную интерпретацию вида `t=1 ч./1 сут./1 ч.`;
- при mixed schedule именно на неё удобнее ориентироваться визуально.

### Что писать в колонке `Family`

Оставляйте:

- `y`
- `p_peak`
- `p_through`
- `n`
- `e`
- `c`

Если схема смешанная, например `p_peak + n`, у разных строк должны быть разные значения в `Family`.

## Типовые сценарии работы в predictor

### Сценарий 1. Стандартный прогноз по одному treated-файлу

1. Откройте `Growth predictor`.
2. В `Files` загрузите:
   - `Open treated file`
   - `Open control file`
3. В `Tumor` выберите:
   - `Mean across rats`
4. В `Alpha/Beta source` выберите нужный fitter run.
5. Нажмите `Fit growth from control`.
6. Нажмите `Use treated fractions`.
7. Нажмите `Simulate`.
8. Смотрите вкладки `Curves` и `3D`.

### Сценарий 2. Полностью ручной прогноз

1. Загрузите только `Treated tumor`.
2. В `Alpha/Beta source` оставьте `Manual`.
3. Вручную задайте:
   - `alpha`
   - `beta`
   - `Growth rate r`
   - `Carrying capacity K`
   - `Clearance rate`
4. Заполните `Dose schedule`.
5. Нажмите `Simulate`.

### Сценарий 3. Короткие интервалы между фракциями

Если вас интересуют схемы с часовыми интервалами:

1. Загрузите treated-файл с `t=...`, либо задайте времена вручную.
2. Поставьте `Repair T1/2 (h) > 0`.
3. Нажмите `Simulate`.

Иначе predictor будет считать фракции независимыми по kill.

### Сценарий 4. Mixed-family schedule

Например, вы хотите сравнить:

- `p_peak + n`
- против `c`

Тогда:

1. В `Schedule` заполните строки с нужными `Family`.
2. Убедитесь, что в fitter уже есть соответствующие результаты для этих family.
3. Выберите разумный baseline в `Alpha/Beta source`.
4. Нажмите `Simulate`.

Если для какой-то family fitter-result не найден, predictor попытается использовать текущие manual/base параметры и отметит это в summary.

## Что делать, если в папке очень много файлов

Рекомендуемый рабочий процесс:

1. В fitter нажмите `Folder`.
2. Нажмите `Inventory`.
3. Разберите папку по family.
4. Назначьте control через `Experiment to control mapping`.
5. Отдельно прогоните:
   - `y`
   - `p_peak`
   - `p_through`
   - `n`
   - `e`
   - `c`
6. Для каждой family:
   - сначала попробуйте `classic_lq`;
   - затем при необходимости `Compare models`;
   - отдельно проверьте timing-aware варианты.
7. Сохраните `Summary CSV`.
8. Уже после этого переходите в `Growth predictor`.

Такой подход почти всегда лучше, чем сразу пытаться строить одну большую общую модель по всей папке.

## Как выбирать модель на практике

### Начинать почти всегда стоит с

- `Response mode = scalar`
- `Model = classic_lq`

### Переходить к `curve` стоит, если

- у вас хорошие длинные кривые;
- endpoint `SF` слишком чувствителен к выбору метрики;
- вы хотите использовать больше информации из серии.

### Переходить к repair-aware моделям стоит, если

- есть `t=...`;
- интервалы реально различаются;
- вас интересует эффект `30 min` vs `1 h` vs `2.5 h` vs `24 h`.

### Переходить к `glq` или `lq_l` стоит, если

- в данных большие разовые дозы;
- хотите проверить high-dose поведение модели.

### Переходить к `let_dependent` стоит, если

- вы хотите общий вывод по качеству излучения;
- у вас есть несколько family с разным LET;
- вас интересует `alpha(LET)` и LET-based `RBE`.

## Частые ошибки и как их избегать

### Ошибка 1. Смешивать разные типы излучения в одном обычном fit

Не делайте так без отдельной причины.

Лучше:

- либо `Family = конкретная family`;
- либо `By family`;
- либо отдельный `let_dependent` анализ.

### Ошибка 2. Игнорировать `t=...` при коротких интервалах

Если интервалы важны, включайте:

- `Repair T1/2 (h)`

### Ошибка 3. Сразу использовать слишком сложную модель на маленьком наборе

Если данных мало, начните с:

- `classic_lq`

и только потом идите в:

- `repair_lq`
- `repair_biexp`
- `glq`
- `lq_l`
- `repair_repop`

### Ошибка 4. Не проверять `Inventory`

Если папка большая, сначала почти всегда нужен:

- `Inventory`

### Ошибка 5. Неправильный control

Если control-файлов несколько, обязательно проверьте:

- `Experiment to control mapping`

## Минимальный рекомендуемый workflow

Если хочется самой короткой рабочей схемы:

1. В `Survival LQ fitter` загрузите файлы.
2. Назначьте control.
3. Нажмите `Inventory`.
4. Выберите одну family.
5. Запустите `Run fit` с:
   - `SF modes = absolute`
   - `Response mode = scalar`
   - `Model = classic_lq`
6. Посмотрите `Run summary`, `Training`, `Summary text`, `Analysis`.
7. Если timing важен, повторите с `Repair T1/2 (h)`.
8. Если high-dose данные хорошие, повторите с `Compare models`.
9. Откройте `Growth predictor`.
10. Загрузите treated/control.
11. Выберите `Alpha/Beta source`.
12. Нажмите `Use treated fractions`.
13. Нажмите `Simulate`.
